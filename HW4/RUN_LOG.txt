Two things worth calling out about this run, following section 0.2's request to identify any
source of non-determinism:

First, the per epoch training losses came back identical to four decimal places to the earlier
CPU run, even though the attention row sum check shows a tiny difference in the eighth decimal
place (0.9999998211860657 on GPU versus 0.9999998807907104 on CPU), so the two runs are not
bit for bit identical under the hood. With a model this small and only 300 total training steps,
those tiny floating point differences never grew large enough to move the rounded loss values.

Second, greedy decoding produced the exact same text on both CPU and GPU, but the temperature
and top-k samples did not. Greedy uses argmax, which has no randomness in it, so as long as the
model's top choice at each step is a clear winner rather than a close call, the CPU and GPU
results agree. Temperature and top-k sampling both call torch.multinomial, which draws from the
CUDA random generator when the logits tensor lives on the GPU and from the CPU generator
otherwise. Those are two different random streams, so the same SEED value does not produce the
same random draws across devices, only within one device. That is the identified source of the
difference. I did not try to force identical sampling across CPU and GPU, since the assignment
only asks for reproducibility on a given piece of hardware, which both Step 4 (CPU, run twice)
and this Colab run each satisfy on their own.

One gap: the checkpoint file itself, checkpoints/mini_gpt_seed_9486.pt, was written on the Colab
instance's local disk during this run but was not part of what got pulled back into this
repository, since Colab's local filesystem is not synced to git. That file will need to be
downloaded from Colab and added to the repo separately, or the notebook re-run somewhere that
does sync, before final submission.
