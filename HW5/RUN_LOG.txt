Step 1: Local Environment Probe
UTC Timestamp: 2026-09-29T01:10:00Z (approx.)
Environment: Apple M1, 8 GB RAM, Python 3.13.9 in a separate virtual environment with
torch 2.14.0, transformers 5.17.0, peft 0.21.0, datasets 5.0.1.
Status: A short probe script confirmed:
  - flan-t5-small's linear layer names are k, lm_head, o, q, v, wi_0, wi_1, wo, so the demo's
    q_proj/v_proj targets do not exist in T5 and LoRA has to target q and v instead.
  - LoRA r=4 on q and v gives 172,032 trainable parameters out of 77,133,184 (0.2230%).
  - Seq2SeqTrainer in transformers 5.x takes processing_class= rather than tokenizer=.
  - Dialogue token lengths: median 202, 95th percentile 421, 99th percentile about 561.
    Summary token lengths: median 36, 99th percentile about 91. This is why max source length
    is 512 and max target length is 128.
  - Training speed at batch size 8: about 3.9 s/step on CPU, and about 77 s/step on Apple MPS
    (much slower, likely due to memory pressure on 8 GB). All local runs below therefore used
    CPU. The notebook passes use_cpu=(device == "cpu") to the Trainer so it does not
    automatically pick MPS on a Mac, which makes no difference on Colab.

Run-to-run and device-to-device differences:
  - Across the three Colab runs (Steps 6, 9, and 10), all parameter counts and all six
    generated summaries were identical. Some losses differed only in the fourth decimal place
    (for example, r=4 at step 250 was 1.5168 in Step 6 and 1.5171 in Step 10, and the r=4 final
    loss was 1.6318 vs 1.6319). Some GPU kernels do not add floating point values in a fixed
    order, so tiny differences like this are expected even with the same SEED.
  - Compared with the local CPU runs (Steps 3 and 4), the parameter counts, evaluation
    dialogues, processed samples, and baseline summaries were identical. The baseline uses the
    unmodified pretrained weights and greedy decoding, so there is no randomness in it.
  - Training losses were close but not identical: r=4 final loss 1.6319 on GPU vs 1.6292 on
    CPU, and r=16 1.6015 on GPU vs 1.6007 on CPU.
  - The r=4 Example 1 output was identical on both devices, but the other three LoRA outputs
    changed. On CPU, r=16 Example 1 ended with "They'll play some Vanilla Ice songs." and did
    not repeat itself. r=4 Example 2 was "#Person2# wants to go to New Orleans tonight.
    #Person2# wants to go to a jazz club and a riverboat tour." and did not mention the theater.
  - The identified source of the difference: LoRA dropout (p=0.1) draws its masks from the CUDA
    random generator on the GPU and from the CPU generator locally. Those are two different
    random streams, so the same SEED gives different dropout masks on each device. On top of
    that, GPU and CPU kernels add floating point values in different orders. The adapters
    therefore end up slightly different, and with greedy decoding a small change in one early
    token can change the rest of the sentence. The run is reproducible on a given device (Step 4
    matched Step 3 exactly, and the Colab summaries matched across all three runs), just not
    word for word across devices.
